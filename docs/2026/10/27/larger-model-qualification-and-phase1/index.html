Terms used in this journal
Model and parameters
The model is the program being trained. Parameters are the adjustable numbers it learns; more parameters do not by themselves prove better skills.
Token and tokenizer
A token is a piece of text, which may be a word, part of a word, or punctuation. The tokenizer decides how to split text into these pieces.
Valid label or target
A next-piece prediction the training or scoring rules actually count. Some positions are excluded, so processed input tokens and valid targets can differ.
Update and checkpoint
An update changes the model after some training examples. A checkpoint saves the model and, when available, the state needed to resume training.
Loss and perplexity
Two measures of text-prediction error. Lower is better on the same test under the same rules. Neither is a reasoning score or has a universal passing mark.
Development panel and holdout
A development panel is a fixed set used while making decisions. A sealed holdout is kept aside for a final check. Repeated development checks are not fresh final tests.
Baseline, control, and transfer
A baseline or control is a reference for a comparison. Transfer means a learned skill still works when the task or setting changes.
Supervised fine-tuning (SFT)
Training on example answers or actions after, or instead of, general text training. Fit to those examples is separate from success on new requests.
Protocol, tool, and receipt
A protocol sets the required output format. A tool is an action the surrounding software can run. A receipt records a tool result, but does not prove it acted on the right object.
Guard and budget
A guard enforces limits such as time or storage. Passing a guard check is evidence about the software, not the model’s intelligence. Reserved work and completed work are different counts.
BF16 and FP32
Number formats used for computation and stored state. FP32 keeps more precision. Different calculation settings can affect whether measurements are strictly comparable.
Hash and provenance
A hash is a fingerprint of exact file contents. Provenance records where data or a model came from. These help trace evidence; they do not by themselves prove quality or rights.
